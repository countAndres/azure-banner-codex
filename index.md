# Azure Banner — Campaign Memory Index

**Purpose:** Entry point for a portable, model-independent memory layer for the *Azure Banner* Dungeons & Dragons campaign.

**Coverage:** Recorded play through the **end of Zazesspur Day 14**, before the party's next-morning audience at the Hall of Measures. The files are condensed continuity references, **not complete transcripts**. They should be reviewed against the original play record when fine mechanical or chronological details matter.

## How to read this memory layer

**To resume the campaign:**

1. Read this `index.md` for structure and continuity rules.
2. Read [`campaign.json`](campaign.json) for the latest recorded characters, assets, shared money, location, and open mission state.
3. Read [`day-14.md`](day-14.md) and, if needed, [`day-13.md`](day-13.md) for the immediate circumstances leading into the next scene.
4. Consult [`scraps.md`](scraps.md) for small character details, NPC mannerisms, deferred plans, loose ends, and atmosphere.
5. Open earlier daily logs **as relevant to a returning person, place, clue, or player question**; there is usually no need to load every file at once.

**To review campaign history:** Read the daily logs chronologically, **including the interlude** between the two log groups. Do not infer that the numbered files describe 14 uninterrupted calendar days.

## Continuity and source-of-truth rules

1. **New confirmed play supersedes old snapshots.** After further sessions, a more recent explicitly accepted record of an event, character choice, or inventory change takes precedence over this Day 14 collection.
2. **For the Day 14 stopping point, start with the JSON snapshot** for active game state. For *how* that state came about, use the relevant daily log and interlude. For a subtle character or world detail, use `scraps.md`.
3. **Do not treat the documents as infallible.** These are summaries of a longer campaign. If sources disagree or a number is missing, flag the discrepancy and ask the player rather than selecting a convenient invention.
4. **Respect status labels.** An idea, reserved NPC, draft future headquarters detail, pending payment, or proposed purchase is **not** an event that occurred or an item already owned. Similarly, evidence turned over to officials is not treasure in the party's cart.
5. **Distinguish NPCs from party members.** Allies who fought or traveled with the trio need not have joined the permanent party; use the specific day's log to establish who was present.
6. **Keep established game conventions.** The campaign draws on **2024 D&D** with house rules, including restricted **Excursion Rests** outside secure locations. Discretionary level-up choices require player review before being treated as final. Do not reconstruct mechanical values from generic rules when an accepted character sheet or play ruling says otherwise.
7. **Preserve uncertainty.** For unreconciled ammunition, item counts, spending, injury status, calendar gaps, or unidentified conspirators, use `unknown` / `unverified` rather than fabricating certainty.

## Updating this repository after play

- **Daily log:** Add a `day-15.md` (and later files) after the corresponding day is actually played. Label the date system explicitly until a single in-world chronology has been agreed. Record major scenes, consequential choices, NPC contact, evidence, outcomes, and end-of-day continuity.
- **Snapshot:** Update the JSON for **confirmed** changes in levels, equipment, shared funds, spell/HP state as tracked, party assets, NPC custody, location, and live quests. Change the snapshot day and stopping point when appropriate.
- **Scraps:** Append new tiny facts, quirks, jokes, promises, and mysteries. Mark threads resolved when played out; keep future-only ideas separate from canon events.
- **Index:** Update the quick handoff, file links, and chronology note when a new installment is added or a conflict is reconciled.
- **Review:** Have the player confirm questionable reconstructions before promoting them to accepted campaign continuity.
